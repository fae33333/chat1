🎙️ LiveKit — البث الصوتي والمرئي المباشر (الراديو والكاميرا والميكروفون)

مقاعد الصوت وبث الكاميرا والشريك (PK) والمكالمات الخاصة والتوافق الصوتي كلها عبر LiveKit. عند الحفظ تُطبَّق الإعدادات فوراً على كل الغرف بلا إعادة تشغيل — من كانوا في غرفة وانتظر البث ينضمون تلقائياً لحظة الحفظ.

🚀 الإنتاج على دومينك (هذا الموقع): wss://live.chat-arab.me:8443
التهيئة الكاملة خطوة بخطوة (DNS + شهادة + nginx/Caddy + Docker) في الدليل: deploy/livekit/README.md
أو وضع التطوير المحلي بأمر واحد، أو LiveKit Cloud:
docker run --rm -p 7880:7880 -p 7881:7881 -p 50051:50051 livekit/livekit-server --dev
متغيرات البيئة المكافئة (بديل الإعداد داخل التطبيق): LIVEKIT_URL / LIVEKIT_API_KEY / LIVEKIT_API_SECRET

ℹ️ سرّ API لا يُعرض مجدداً بعد إغلاق نافذة الإنشاء — انسخه حين تُنشئه، أو أعد توليده لاحقاً (يُستبدل عند الحفظ).

⚙️ تحويل المبالغ إلى نقاط

المُرسل يكسب نقاط الثروة والمستلم يكسب نقاط الرواج بحسب قيمة الهدية. شراء VIP يرفع الثروة أيضاً. المستوى يُحسب تلقائياً من النقاط.

🎴 مميزات مستوى الثروة (البطاقات التي تُفتح للعضو حسب مستواه)

تظهر هذه البطاقات للعضو عند نقره على شارة الثروة. البطاقة مقفلة حتى يبلغ مستوى الفتح، وعند النقر عليها تظهر نافذة بوصفها. ملاحظة: الامتيازات ذات المفتاح التقني (الظاهر تحت الاسم) تُطبَّق فعلياً في الخادم حسب «يُفتح عند مستوى» ومفتاح «مفعّل»: «لا يمكن طردك من الغرف» (حصانة الكتم والطرد والإنزال من المايك)، «زيادة عدد المتابعين» (حد المتابعة أدناه)، «إعلان عالمي» (بث رسالة لكل الغرف). وعند بلوغ العضو مستوى الفتح يصله إشعار فوري. أما «فقاعة الدردشة» و«الإطار» و«الدخوليات» و«بطاقة الغرفة» فتُمنح عناصرها فعلياً من «مكافآت المستويات» أعلاه. بقية البطاقات عرض ووصف.

⚠️ أخطاء شائعة تسبب redirect_uri_mismatch: فرق http/https، وجود www. أو عدمه، فارق المنفذ (:3000 / :2083)، أو شرطة مائلة / نهائية — أضف كل العناوين التي تدخل منها (Google يسمح بعدة عناوين في نفس الوقت).
📖 كيف تحصل على Client ID و Secret؟ (وخريجة إصلاح redirect_uri_mismatch)
  1. ادخل console.cloud.google.com ← APIs & Services ← OAuth consent screen واكتب اسم التطبيق.
  2. Credentials ← Create Credentials ← OAuth client ID ← نوع Web application.
  3. في Authorized redirect URIs أضف العناوين الظاهرة أعلاه (① و ②) حرفياً، وأضف معها كل عنوان تدخل منه فعلاً مثل http://localhost:3000/api/auth/google/callback أو https://yourdomain:2083/api/auth/google/callback — Google يسمح بعدة عناوين.
  4. في Authorized JavaScript origins أضف أصل الموقع ③ (مثلاً https://yourdomain.com بدون مسار).
  5. انسخ Client ID و Client secret والصقهما هنا ثم احفظ — يُفعَّل فوراً بدون إعادة تشغيل.
  6. لو ظهر خطأ 400 redirect_uri_mismatch مرة أخرى: افتح عناوين Google Console وقارنها بالعنوان ② بالضبط (نفس البروتوكول www والمنفذ وبدون شرطة مائلة نهائية).
